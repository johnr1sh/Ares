# Architecture Decision Records

Use one numbered file per decision: docs/adr/NNNN-short-title.md.

## Template

- Status: proposed, accepted, superseded, or rejected
- Date:
- Decision owners:

### Context and problem

What must be decided, and which requirements/invariants apply?

### Constraints

Platforms, security, privacy, performance, reliability, maintenance and cost constraints.

### Options considered

Include the do-nothing option and credible existing standards/libraries.

### Evidence

Primary sources, implementation versions, experiments, test topology, raw results and uncertainty. Label facts, hypotheses and assumptions.

### Decision

State the selected option and why. If no option is mature enough, record that explicitly.

### Consequences

Compatibility, operational, security, privacy, performance and maintenance consequences.

### Validation and reversal conditions

Tests required to validate the decision and the evidence that would justify changing it.
